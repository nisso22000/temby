## Confirmed causes and fixes

1. The Node relay discarded opaque verification headers generated by the real browser script. Preserving their exact end-to-end values changed its response from 2,889-byte verification HTML to about 724 KB of real HTML. No proof value was generated, forged or patched.
2. The document-policy guard rejected HTML fetched as data and returned before saving its Set-Cookie. Separating data from rewritten documents and applying response cookies first allowed the next navigation to receive full HTML with additional cookies.
3. The CSP guard blanket-rejected response-header policies. They are now retained unchanged for browser enforcement. Policy markup detection uses parsed attributes instead of matching incidental text such as element.integrity assignment.
4. Ultraviolet renamed security attributes and ordinarily rewrote protected resources. The current path preserves integrity/nonce/crossorigin/sandbox attributes, returns integrity-protected resource bytes unchanged, and keeps the browser's original hash check.
5. External localhost helper URLs did not satisfy the merchant's CSP source list. Trusted local helpers are delivered inline where inline code is allowed. Correct namespace/parent links prevent HTML serialization from corrupting their JavaScript.
6. Rewritten localhost resource URLs also failed the unchanged CSP. Assets and API URLs now keep their original origin; the controlling worker intercepts and relays them locally. Navigation URLs remain under localhost.
7. The page still constructed default BareMux while the worker used our adapter. Both now use the custom relay, removing a dependency on missing browser BareMux configuration.

Earlier fixes include import argument ordering, virtual cookie delivery, immediate-write ordering, cold-link worker startup, Origin/Referer mapping and accidental legacy fallback requests. These are separate from current upstream API restrictions.
