# Active proxy behavior and remaining limits

Current revision is v36. It supersedes older statements below about sign-in SDK allowlisting, all-resource relay routing, image/font-only streaming, cooldown retention and aggregate diagnostics. Current behavior and controls are documented in README.md, ARCHITECTURE.md and LAUNCH-READINESS.md. Authentication challenges, token-touch failures, unsupported workers/WebSockets and production deployment boundaries remain unresolved; v36 does not certify public launch readiness.

V36 is a local-use reliability/performance revision. It retains the narrow login-return repair and cookie authority while fixing mobile cart observation, improving resource routing and bounding upstream work. It does not promise full Temu compatibility or public-hosting readiness.

The default entry redirects to the Ultraviolet rewriting relay. It injects engine helpers and the companion described in COMPANION.md; no storefront replacement, purchasing automation or enabled payment integration is present. No active path-name login/order filter or session-wide denial latch remains. The relay contains no instruction to navigate to login; upstream redirects and page JavaScript can do that. This does not prove all unexpected authentication behavior is upstream: cookie/header/origin compatibility still needs verification.

## Local controls still present

- Destination policy: HTTPS port 443, no URL credentials. Only Temu and kwcdn domains/subdomains are allowed. Google/Facebook/Apple sign-in hosts are denied. Actual relay connection DNS answers must all be public; internal networks remain inaccessible. Direct delivery is limited to eligible public CDN resources in the browser.
- The page's explicit Authorization header now forwards unchanged, like other end-to-end headers. The incoming localhost request's credentials are not copied. Hop-by-hop, proxy-authentication and forwarded-host headers remain filtered. Origin/Referer are mapped to permitted upstream origins. Cookie forwarding combines virtual page cookies with the server jar, with HttpOnly values taking precedence.
- Sessions expire after one hour idle and are held only in memory. Server restart loses cookie jars and test-inbox associations; browser virtual storage persists separately. Temu retains its own expiry rules.
- Version 24 repairs known same-merchant login return parameters containing this proxy's localhost URL, without changing unrelated query bytes or authentication decisions. Response cookies are committed before transport handoff and document initialization; script-cookie writes follow the current virtual page. UV script-cookie deletion/expiry is authoritative, with server authority retained for HttpOnly cookies. These fixes do not establish the cause or elimination of upstream token-touch 424/error40001.
- Upstream 401/403 responses pass through. A 429 establishes a cooldown only with explicit future Retry-After. Keys include session, URL, method, forwarded credential/header context and body; distinct operations do not receive the first operation's refusal. Body retention is bounded and replays are recorded. Unrelated requests continue; no automatic retry is added.
- Responses are limited to 12 MB decoded, with connection/request timeouts. Larger responses and slow operations can fail locally.
- Negotiated binary transport and legacy compatibility remain. Successful unchanged GET image/font/style/media/track and recognized binary bodies stream with backpressure and a 12 MiB decoded limit. Only complete eligible streamed bodies up to 2 MiB are collected for caching. Documents/ordinary scripts/JSON/errors and legacy responses remain buffered. GET/HEAD cancellation stops abandoned reads; mutating requests retain their previous behavior. Eligible public CDN assets and declared protected scripts can bypass the relay, preserving browser CORS/CSP/integrity enforcement. No speculative rewritten-JavaScript cache is added. Helper packaging retains file-change invalidation, ETags and cached escaping.
- Dedicated classic workers use the custom relay, without BareMux message-port initialization. Version 20 also preserves blob URLs, resolves UV's virtual blob URLs to native URLs, and registers generated worker context with the controlling worker. The owned browser blob-worker API test passed. Context metadata is bounded to 128 entries, expires after 30 minutes and survives service-worker termination using local CacheStorage. Arbitrary module/nested/opaque-frame cases are not comprehensively verified; unresolved contexts return a local 502 instead of attempting a direct merchant request. Original CSP can still block worker construction. WebSockets, shared workers and merchant service workers remain unsupported. Documents declaring CSP meta are refused; response-header CSP and original integrity checks are retained. Protected resource bytes are not rewritten.
- The worker controls /uv-service/. Escaped paths can recover using a same-origin encoded proxy-page referrer; a 307 preserves POST methods/bodies, including CSP reports. GET/HEAD on the confirmed /search_result.html and /bgn_verification.html paths can also recover without a referrer through explicit mappings to www.temu.com. Other unidentified local routes still return 404 rather than guessing a merchant URL.
- Native navigation coverage now includes window.open and cancelable browser Navigation API GET events to merchant destinations. This covers scripts delivered unchanged for integrity. It does not intercept history traversal, downloads, or replay native POST bodies. Browsers without the Navigation API have reduced coverage. Opening a product in a new tab is preserved; its URL should still use the localhost proxy prefix.
- Local endpoints enforce loopback binding, Host/Origin checks, request-size/method limits, and no cross-site callers. These do not select merchant login routes.
- Known browser CSP-report POSTs are forwarded directly to the original Temu endpoint without 307 recovery; report bodies are not logged. This separate reporting-only forwarder retains its own 60-second fallback after a report 429 without Retry-After to limit report storms; it does not block search, carts, navigation or payment. Security policies themselves are not stripped. Local injected helper source-map directives are removed to avoid unnecessary DevTools requests under the merchant CSP.
- UV's iframe access wrapper now preserves the native getter when its helper probe encounters a SecurityError. Native cross-origin access restrictions remain; this does not make protected frames readable.
- Request-object cloning retains native method/body behavior rather than passing through UV URL stringification. Dynamic srcset properties retain upstream image URLs for CSP. Cross-origin resource remapping uses the actual controlled client URL as the physical referrer so UV can reconstruct virtual page context after browser referrer reduction.
- /api/health exposes bounded failure aggregates for the requesting session only: redacted API names, numeric codes, statuses and counts. /api/metrics separates upstream, cache/coalesced, cooldown, blocked, cancellation and local/browser events for that same session. Neither exposes query values, bodies or session identifiers. HTTP 200 alone is not treated as application success; explicit success=false is recorded as an application failure. Hosted access control, persistence and secure origin configuration remain launch requirements.

## Removed implementations

The old Scramjet and plain transport experiments, /_p relay, cart/payment demo and old probing scripts have been removed from the working tree and dependency graph. UV is the only active engine. Synthetic UV regression fixtures remain test-only and require explicit server configuration; they are disabled with normal npm start. Dated historical reports are retained as evidence, not active configuration.
