# Localhost Temu proxy experiment

Run npm start and open http://localhost:3000. The address stays under localhost; there is no home-page flow, outer iframe, remote browser or system proxy.

See [PROXY-LIMITS.md](PROXY-LIMITS.md) for the current local controls and remaining compatibility limits. This inventory supersedes older descriptions of exact host lists and Authorization filtering.

**Current status:** the real anonymous homepage now renders product cards and loads images while scrolling under localhost. A live run showed 40 product links and 74 images; another batch of merchant products was not verified. Controlled three-page pagination, Request cloning, virtual referrer context and dynamic responsive images pass under CSP. Some merchant SEO/cart/chat requests still fail, and OTP login, signed-in shopping and checkout remain unverified. There is no session-wide denial latch. No credentials were entered by the agent.

## Windows setup

Node 24.15.0 was used (minimum 22.19).

```powershell
Set-Location 'C:\Users\Mecro\Documents\ChatGPT\TEMBY'
npm ci --ignore-scripts --offline=false --prefer-online --cache .npm-cache
npm run typecheck
npm test
npm start
```

Both listeners bind to 127.0.0.1. PORT and MERCHANT_PORT optionally override 3000 and 3001. Stop with Ctrl+C. Restart after server-source changes. No public tunnel is configured.

## How the current proxy works

Ultraviolet rewrites page navigation to /uv-service/ on localhost. Asset/API URLs retain their original upstream form so the original CSP still applies; the controlling service worker intercepts those requests and sends them through the restricted local Node relay. Local engine helpers are inserted inline. Integrity-protected resources retain their exact bytes and original integrity attributes, and the browser still verifies the original hash.

The relay preserves end-to-end headers generated by the real page, including its Authorization header and opaque verification fields. It does not generate proof values. Local credentials, proxy authorization, hop-by-hop headers and host overrides remain blocked. Server response cookies are processed independently from HTML rewriting.

Version 21 uses a binary response envelope instead of base64 JSON when the browser requests it; older clients retain the original protocol. Eligible public kwcdn image/style/script/font responses are cached in memory (32 MB / 256 entries, at most one hour and never beyond upstream freshness). APIs, personalized responses, errors, Set-Cookie, Vary, authorized requests and range requests are excluded. Upstream bodies are still bounded and fully downloaded before rewriting. Restart npm start after server changes, then reopen the launcher to activate worker version 21. No performance benchmark was run for this change.

Engine decision: retain UV for this optimization pass. Scramjet's current upstream README describes it as experimental; switching is not an established performance fix for Temu. A later migration should be an independent compatibility change, preserving the working UV fallback. Source: https://github.com/MercuryWorkshop/scramjet.

## Investigation URLs

- http://localhost:3000 — default proxy entry.
- http://localhost:3001/uv/?fixture — explicitly synthetic owned test page.
- http://localhost:3001/uv-service/https%3A%2F%2Ffixture.temby.invalid%2Fcsp-check — owned CSP/SRI/API test after worker startup; not a Temu storefront.
- http://localhost:3000/diagnostics — retained development metadata panel, outside the default flow.
- /engine/ — older Scramjet comparison, incomplete.
- /plain-launch/ — transport-only diagnostic; not the supported browsing flow.

Direct saved /uv-service/ links initialize the worker automatically. Disabled service workers/site storage produce a bounded startup error instead of endless reloads.

The active relay has no shopping workflow or login/order path filters. It forwards ordinary page and form requests and preserves upstream errors. A 401/403 no longer disables the session. A 429 is retained for that method/URL until Retry-After (60 seconds if absent), while unrelated requests continue. No automatic retry is performed. Full login and purchase functionality has not been verified.

No real cart or checkout has been verified. Synthetic fixture values never populate the real cart. No payment or credentials were entered. Per-session server cookies expire after 30 minutes; browser virtual storage is not production multi-user isolation.
